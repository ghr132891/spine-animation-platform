# Spine AI 动画工作台

> 代码交付入口：见 [部署说明](docs/DEPLOYMENT.md) 和 [平台架构](docs/ARCHITECTURE.md)。仓库包含后端、网页、Spine runtime、Skill/MCP、测试与打包工具；不含服务端凭据、用户原图、任务记录或生成成果。下文保留历史开发与验证记录，提到的本机 evidence/outputs 文件不随仓库分发。

当前网页入口为 `/auto.html`，支持上传角色、后台 Codex 辅助制作以及自然语言微调。自动修复默认4次；可播放但尚未通过验收的版本以草稿交付，正式验收状态独立记录。

将原资源导入，进行保持骨骼的换皮，或打开第二步“骨骼＋贴图”编辑新角色。默认监听 `0.0.0.0:8780`，支持同一局域网访问。

双击 [Start.command](Start.command)，或运行：

```sh
python3 app/server.py --host 0.0.0.0 --port 8780
```

需要 Python 3.10+、Pillow、numpy。当前电脑直接使用启动脚本中检测到的内置 Python，无需安装新依赖。启动后打开 <http://127.0.0.1:8780/>；凭据填写页为 <http://127.0.0.1:8780/settings.html>。

局域网设备使用 `http://服务器局域网IP:8780/`，网页和 Agent API 都可访问；`0.0.0.0` 是监听地址，不是其他设备的访问地址。Agent 命令行加 `--base http://服务器局域网IP:8780`。需要仅限本机时可指定 `--host 127.0.0.1`。

`Start.command` 会在后台启动服务，关闭启动终端或浏览器不会停止服务。重启电脑后需再次双击启动；日志保存在 `storage/server.log`。直接运行 Python 命令时，仍需保持该终端运行。

## 可用功能

- 上传 JSON/SKEL + atlas + 全部 PNG，或导入 ZIP；保留子目录结构。
- 部件列表、单选/多选、原始未裁切部件下载、图集页下载。
- 色相/饱和度/明度调整、上传同尺寸新部件、整页图集替换。
- 恢复原部件、撤销最近一次编辑、每次编辑自动保存历史版本、命名保存、恢复旧版本，以及刷新/重开后的项目恢复。
- 顶部“历史记录”可查看所有项目、全部编辑版本和全部 AI 候选；AI 状态由本地服务继续查询并保存，切换部件或关闭页面不会中断结果收集。
- 官方 Spine 3.8 / 4.2 双画布预览，切换动作、皮肤、速度、骨骼显示和整体左右镜像。镜像是预览设置；游戏中仍应按移动方向整体翻转角色。
- 亿创 API Key 在本地输入并验证，验证后以 `0600` 文件权限存入 `storage/credentials.json`，不返回到浏览器，不包含在导出包。
- AI 材质生成 → 按原轮廓生成候选部件 → 明确应用 → 导出。也支持 HTTPS 参考画布重绘。
- 导出前验证骨骼、动画和 atlas 的字节一致性，PNG 的尺寸与 alpha 一致性。导出 ZIP 保留原文件名，附 `_reskin-validation.json`。
- AI Agent 自动任务接口：输入 Spine 资源或已有项目、目标风格，自动生成部件提示词、调用亿创、替换贴图并导出新项目。支持计划预览、进度查询、幂等提交、恢复与下载；详见 [Agent 调用说明](agent/README.md) 和 [OpenAPI](agent/openapi.json)。

## 已验证与边界

本机已用新 API Key 调通模型列表，并完成 nano-banana-2 材质生成、下载、贴回部件和不变量校验。真实 AI 任务记录见 `evidence/material-result.json`。这是材质填充路线，不能标称为已经验证了整套角色的 AI 图生图重绘。

已实测 nano-banana-2 不接受 data URI 参考图（任务接受后，单项输出报 InvalidSchema）；GPT Image 2 的该输入提交也被拒绝。因此工具不把 Base64 参考图作为可用能力。此为早期模型验证记录。当前新生图使用亿创 GPT Image 2.5 Flare；参考图模式需要工具生成的 512×512 部件画布对应的 HTTPS URL，AutoReskin 仍需部件链接映射。1.7.1 的服务端免登录发布仅接入单图动画补图，可使用临时 HTTPS 通道或可选 S3 存储。

第一步编辑器支持 legacy `xy/size/orig/offset` 与 compact `bounds/offsets`，多页 PNG、正交旋转、trim 与显式 PMA。第一步透明轮廓锁定，不能增加新轮廓、骨骼或附件。JSON/SKEL 完全不改，保留已有 mesh、weights、deform、IK、events 和动画数据；本次没有验证所有这类复杂资源的实际视觉效果。

在线预览只提供 3.8/4.2 两个 runtime，其他版本导出后需使用匹配引擎检查。旧资源未声明 PMA 时不能凭图片自动可靠判断；混合 PMA 页的预览可能需在目标引擎检查。`.spine` 工程不解析，需先导出 JSON/SKEL + atlas + PNG。

## 第二步：骨骼＋贴图（2026-10-08）

顶部“骨骼＋贴图”打开 `rig.html`。从当前换皮项目创建独立方案，继承当前贴图与完整 JSON；也可重新打开已保存方案。第二步资源在 `storage/rigs/`，完整状态与版本索引一次原子提交，部件图片以内容摘要独立保存。

- 骨架：编辑骨骼位置、旋转、缩放、长度、名称、父骨骼；新增控制骨骼；删除不被插槽、子骨骼、蒙皮、约束或皮肤引用的叶骨骼。修改名称会同步更新动画和约束的名称引用。重排骨骼时会映射加权顶点中的骨骼索引。
- 贴图：上传任意尺寸、自由 alpha 的 PNG；重打多页图集，保留完整画布，并给边缘加 2px 扩边。可选择按新像素尺寸调整普通 region 附件的几何尺寸；mesh 仍使用原 UV 与蒙皮范围。
- 附件：新增普通图片附件并绑定骨骼、编辑 region 附件偏移/大小/旋转、重新绑定插槽、删除附件并清理对应变形动画与图片引用。删除保留空插槽以维持已有绘制顺序；可在“插槽骨骼绑定”中重新绑定空插槽后删除无引用骨骼。
- IK：修改链条、目标、混合、柔化、弯曲方向。双骨 IK 必须保持连续父子链；动画的 IK 关键帧可能覆盖初始混合值。
- 完整替换：可下载当前 JSON，在匹配版本 Spine 中编辑或用其他方式重建，再上传相同版本的完整骨架 JSON。它须引用当前图集里的区域；可先新增对应部件。导入骨架会使用其自身的骨骼索引，结构校验失败时不会覆盖现有状态。
- AI：继承第一步当前生成结果，也可应用第一步已经保存的同部件候选。新材质生成仍在第一步完成；第二步不会重新提交历史任务。
- 历史：每次操作保存整个骨架和全部贴图，支持命名、恢复、重开。恢复会另存一个新版本。
- 导出：`skeleton.json`、`skeleton.atlas`、`rig-page-*.png`、`images/` 原部件、结构与打包像素校验报告。可把 JSON 导回匹配版本的 Spine 编辑器；不生成原生 `.spine` 或二进制 `.skel`。

此入口限 Spine 3.8 / 4.2 JSON。SKEL 请先在 Spine 中导出 JSON。序列图集暂不支持；不能通过改版本号转换 Spine 数据。mesh、权重、deform、IK 和 events 延续原数据，改变骨架后需要逐动作检查。保留的是局部动画曲线；不同拓扑之间自动保持世界空间动作、自动重新蒙皮，属于后续工作，未标称为已完成。第三步的单图人形拆件与新建行走已独立接入，见下文。

参考流程：[GenielabsOpenSource/spine-animation-ai](https://github.com/GenielabsOpenSource/spine-animation-ai)。该仓库采用非商业许可，本工作台未复制其实现或示例素材。结构依据 [Spine JSON 格式](https://esotericsoftware.com/spine-json-format)。

## 骨骼定位与移动体验

选择骨骼后，预览用粉色标记关节点、骨长和名称，用蓝色轮廓标记受影响贴图，虚线显示子骨骼联系。顶部同步显示选中名称和影响的部件。蒙皮说明按真实顶点权重和骨骼层级计算，包含 linkedmesh 的继承关系；不会仅凭插槽绑定骨骼判断影响范围。

可点击右侧画布关节点或骨段选中骨骼，列表与表单同步。动画播放时，重叠关节点可反复点击切换；初始姿态下重叠节点优先使用当前选择，可从列表明确选择。点击“初始姿态定位”，再拖动已选的粉色关节点。X/Y 会同步到右侧表单。

修改位置、旋转、缩放和长度会即时预览，显示“未保存的预览”；点击“应用骨骼修改”才写入版本。“取消未保存的预览”恢复当前版本。切换所选骨骼会放弃该骨骼未应用的预览。父子关系和名称的修改在应用后更新。第一步换皮预览不启用这套编辑覆盖层。

验证命令：`node tools/verify_bone_inspector.cjs`、`node tools/verify_rig_dom.cjs`。离线测试直接使用官方 3.8 / 4.2 的相机、骨架、IK 和网格对象，覆盖高亮、蒙皮影响、镜像投影/反投影、父骨骼反变换、拖动、取消预览，以及 production viewer 的 controls 处理。SVG/三角形离线渲染示意可由 `python3 tools/render_bone_inspector.py` 生成，不属于浏览器截图。

“自动动作重定向”指把 A 骨架的动作迁移到不同结构的 B 骨架，自动匹配关节、转换曲线并补偿比例。当前可在同一个角色中调整骨架并沿用局部动作曲线；完全换成另一套骨架时，需要为它匹配或制作动作。改变比例后也应检查脚掌接地与关节接缝。

## 第三步：根据一张图片制作行走

入口：`http://127.0.0.1:8780/character.html`。主页及骨骼页顶部提供三个步骤的导航。

1. 上传一张角色 PNG / JPG / WebP，或用已配置的亿创生成一张全身角色图。新接口使用独立的角色立绘提示词，不经过第一步的材质提示词。实际示例已通过 nano-banana-2 生成，没有用几何机器人替代 AI 图。
2. 纯色背景按边缘连通区域去除，保留内部白色衣物；可选清理腿间封闭背景，完整部件边界可作为额外背景判定。透明 PNG 保留原 alpha。轮廓比例提供推荐关节点，可在 SVG 原图上拖动、填写坐标及使用方向键移动。
3. 初始拆分按关节线段距离计算，支持为各部件圈定多边形修正。原图 alpha 限定最终轮廓，只在真实共用关节附近保留与当前部件相接的窄小重叠，避免肘部、下巴或鞋子串入邻近部件；原始组装覆盖全部可见像素。部件卡片可在原图位置高亮定位。
4. 建立 16 根骨骼和 15 张加权网格附件（可选背部为第 16 张）。同一肢体链内的部件沿同一原图网格采样，关节共享顶点具有一致权重和局部坐标；左右手臂、左右腿、身体使用独立权重，只在肩/髋连接处绑定父骨骼。边界复制两像素，防止线性过滤露缝。程序求解双腿的目标轨迹并烘焙旋转关键帧，支撑阶段保持原踝点高度，脚踝补偿父骨骼旋转；配合摆臂、身体上下运动，包含 idle / walk。预览支持初始姿态、速度、整体镜像和骨骼显示。
5. 关节、边界、步幅等设置保存到本机，每次制作建立独立的第一步源项目和第二步骨骼项目。历史可恢复配置，新版本不会覆盖旧方案的骨骼编辑。导出包含 Spine 4.2 JSON、atlas、图集 PNG、images 部件、原图、关节点及版本信息；可继续进入骨骼与贴图编辑器。

遮挡补全：一张合成人物图无法提供被其他部件挡住的像素，改蒙皮或复制邻近素材不能恢复完整背包、手臂和鞋子。“拆分部件 → 亿创生成完整部件”使用当前亿创角色的 HTTPS 参考图生成身体/背包、手臂、双腿三组独立贴图。结果持久保存，检查后逐组应用；不会把整张部件图误用作角色原图。生成模型可能改变排版、朝向或画出多余部件，需检查生成结果，必要时补做某组。当前实例实际用了三组加一组修正的前臂/手部图，已检查分格、去背景、鞋子朝向和关节位置。

候选应用默认“只补遮挡，保留原图”：原图中已拆出的可见像素逐像素保留，参考生成的贴图只填入边界内被其他部件遮住的位置，不移动原有关节。版本标记 `occlusion-fill-v1`，部件按原图坐标保存，原关节位置下直接使用原始像素，不进行缩放重采样。身体和四肢继续使用分链蒙皮；鞋子保持刚性，小腿在鞋口附近渐变绑定到同一脚骨，避免迈步时鞋口露缝。当前机器人另用原图近侧鞋的完整鞋跟补齐后侧鞋缺失处，保留原鞋造型。

贴图存储在不可变的 `part-images/` 文件中；可以恢复单个部件的原图拆分，或者通过历史恢复整个旧方案。旧图和旧贴图不会被覆盖；导出另外包含 `single-image/complete-parts/` 和版本所用的源坐标锚点。之前整块重绘的 `complete-parts-v1` 版本仍在历史中，它使用普通图片附件，AI 可能改变可见细节和比例。1.7.1 起，管理员可启用临时 HTTPS 通道替代存储配置；已有 ready 的 S3 兼容存储优先。本地角色原图由平台服务端自动发布、校验并关联 HTTPS 参考图，使用者无需亿创网页登录；后续按当前原图哈希复用，过期或重启失效后自动刷新。

适用范围：站立且四肢清晰的人形双足角色。推荐点位不是 AI 任意姿态识别，复杂照片须先准备透明 PNG；单图不包含遮挡区域，运动后可能露缝，需要调整边界、步幅或补充贴图。新行走由此骨架生成，不是不同骨架的动作重定向。不输出原生 `.spine` 或 `.skel`。

角色和 AI 任务保存在 `storage/characters/`。任务提交前持久化，nonce 去重；未知提交不会重发，服务重启只恢复轮询/下载。导出不包含亿创凭据。

## 组装校准与拆分检查（2026-10-09）

参考 spine-animation-ai 的“拆件 → 对照原图摆放 → 校准层级 → 制作动画”流程，新增第三步的 **组装校准** 标签页。实现独立编写，未复制参考仓库代码或素材。

- 原图与组装并排显示；选中部件有轮廓框和锚点，可拖动、用方向键移动，或输入横移、纵移、旋转、缩放。提供原图叠加和单部件查看。
- 前后移动层级、单部件复位、全部复位。校准保存到本机；制作行走时应用到贴图几何及 Spine 插槽顺序，保持骨骼和动作曲线。零校准直接使用原始像素，不做重采样。
- 连通像素块检查提示可能串入的邻近部件或断开的连接；补全超过 20% 提示对照原图。检查不会删除零碎装饰，也不代表模型已判断部件正确。它不自动恢复缺失的遮挡像素。
- 校准随新行走版本保存；“恢复制作配置”恢复该版关节、边界、部件、步幅与校准。旧版本没有校准字段时按零校准恢复。导出新增 `single-image/assembly-review.json`，可供 AI 读取和继续调整。

API：`GET /api/characters/{id}/review` 返回原图尺寸、部件边界、锚点、当前调整、绘制顺序和检查结果；`POST` 同一路径保存 `{revision, part_review: {adjustments, draw_order}}`。`adjustments` 按部件名称记录 `{dx, dy, rotation, scale}`；坐标是原图像素，Y 向下、旋转顺时针，**不是 Spine 的 Y 向上坐标**。偏移上限为原图长边的一半，旋转 ±90°，缩放 0.5–2。`draw_order` 必须包含当前所有部件各一次，从后到前。POST 使用现有 `X-Spine-Local: 1` 操作头。

`GET /api/characters/{id}/assembly` 获取按当前顺序组装的透明 PNG；`GET /api/characters/{id}/part?name=torso&unadjusted=1` 获取零校准部件。原图与旧行走版本不会被这些读取操作修改。保存校准后需制作新版本，已有动画继续显示原版本。

本次加入连通块诊断和人工组装校准；参考项目的 SIFT/RANSAC 自动配准、自动遮挡层级推断及更多动作预设尚未接入。较大校准可能影响关节衔接，必须检查完整行走周期。

验证：全量 56 项测试通过；`tools/verify_character_dom.cjs` 验证拖动、表单、层级、保存和制作；`tools/prepare_review_example.py` 在独立目录生成验收数据，`tools/verify_part_review_runtime.cjs` 用官方 4.2 runtime 对 idle / walk 各采样 49 帧，确认仅被调整部件的几何变化、其他部件误差为 0、骨骼曲线不变、循环误差为 0。浏览器实际检查了校准页加载、部件选择、定位和排版；全部编辑动作的浏览器验收仍需补齐。记录在 `evidence/assembly-review/`。本次未提交新的 AI 生图。

Agent API 默认无需令牌（1.4.1）：Skill/MCP 安装只需平台地址。可选 `SPINE_AGENT_REQUIRE_TOKEN=1` 恢复令牌模式；内部会话签名文件仍由服务器保管。

简易网页同样默认无需访问码：局域网／VPN用户打开 `/auto.html` 即自动连接，签名 Cookie 保留各浏览器自己的制作记录，远程访客仍为普通用户。可选 `SPINE_WEB_REQUIRE_CODE=1` 恢复网页访问码模式；未设置时跟随 Agent 的开放／保护设置。分享开放页面只需提供页面地址。


### 后续生成模型与免登录参考图（1.7.1）

工作台、批量和 Agent 生图统一调用亿创 `gpt-image-2.5-flare`，默认 high、1K、PNG，每次 1 张。参考编辑使用 `input_images` 的 HTTPS URL。新任务在提交前记录 model；无 model 的历史记录仍按 nano-banana-2 查询，不重复提交旧任务。

使用者安装 Skill/MCP 并连接平台后，只把角色图片和动作要求发给 Codex。`spine_submit` 发送图片，后台检查视角与遮挡；新任务默认先准备完整部件图，服务器自动准备参考图链接、调用亿创，再由Codex检查实际裁片与组装后绑定和制作。已有合格完整部件图可以直接复用。使用者不登录亿创、不复制 HTTPS 链接、不提供亿创或存储凭据。

管理员可在服务机器打开 `http://127.0.0.1:8780/settings.html` 启用临时 HTTPS 参考图通道，使用官方 `tools/bin/cloudflared` 客户端；无需对象存储账户、Cloudflare 账户、域名或存储密钥。通道连接独立 loopback PNG 图片服务器，仅允许随机 token 对应的 PNG GET/HEAD，不暴露工作台、目录或其他接口；持有有效链接者可读取对应原图。图片有效期1小时，服务重启旧链接失效，平台再次需要时自动刷新缓存。服务端回读校验像素后按哈希缓存。

S3 兼容存储仍可选，已有 ready 配置优先。管理员可本机保存 endpoint、region、bucket、access_key_id、secret_access_key、prefix 与签名链接有效期，签名过期会刷新；凭据不返回客户端、不打入分发包。发布器只负责参考图链接，所有图片生成仍使用亿创 Flare。

[Cloudflare 官方说明](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)将 Quick Tunnel 定位为测试与开发功能，没有 uptime 保证，启动后临时域名会变化。服务机与网络必须保持运行；此通道只供亿创读取参考图，其他使用者仍通过局域网／VPN 连接平台，不将工作台端口公开到互联网。

`spine_sources.reference_upload.ready` 提供发布配置状态。`spine_reference action="ensure"` 可在当前角色与 revision 下显式准备链接，通常直接生成即可自动处理。`GET /api/characters/{id}/reference` 保持只读；`prepare`／`register` 保留可选兼容。原图改变后使用新缓存，不会误用旧链接、丢弃参考图或回退其他模型。发布不占生图额度，失败时保留任务并明确由管理员处理。

发布器未就绪、客户端缺失或网络不通时保留任务并报告具体平台原因，不要求普通使用者登录亿创或配置存储。代码接入、模拟测试和发布器 ready 状态不代表免登录实图全链路已验收；需分别完成真实发布、像素校验、Flare 结果复查及动作多帧检查，才能给出对应阶段的成功结论。AutoReskin 的 `reference_urls` 仍要求各部件 512×512 画布的链接映射，本轮没有改为自动发布。

2026-10-10 临时通道实图验证：蓝衣武者参考 PNG 经独立图片通道发布、远端像素校验，通过亿创 GPT Image 2.5 Flare 完成一次图生图，约41秒获得896×1200白底结果。角色身份、配色、服装、站姿及完整手脚基本保持，局部轮廓和纹理有轻微重绘差异。总计只提交1次生成；测试通道已关闭，平台已启用按需临时通道模式。记录与原图／结果在 `evidence/quick-tunnel-20261010/`。此验证覆盖参考图传输与图生图，未制作或验收新的 Spine。

### 部件救回和动作诊断（1.8.0）

部件提示词按身体、双臂、腿脚分组，支持无背包角色的三部件身体布局。Codex 可按候选图真实像素布局接入完整肢体或组合裁片，采用连续加权并删除同侧旧分段附件，减少错排后重复生图。该流程需要 Codex 看图确定内容和关节，不是自动解剖检测。

交付增加官方 runtime 的旋转字段检查、真实可见和相对父骨运动诊断；明确行走需求的 walk/run 至少16帧预览，最终建议32帧检查。已更新 spine-animation Skill、MCP 和安装包，普通调用方式不变。详见 [本次流程复盘](docs/warrior-flow-lessons-20261010.md)；提示词优化尚需后续真实生成验收，不保证模型严格排版或自然步态。


### 1.8.1 接地与完整肢体

新建人形行走默认抬脚7%、60%支撑期，双腿共用较短链长确定的步幅与场景速度，配合平顺摆腿目标和按步长缩放的摆臂；完整刚性鞋依据完整alpha下轮廓估计鞋底方向与踝目标，并检查双骨可达范围。缺少完整鞋时明确使用ankle-fallback；数学目标不能替代最终不透明鞋底验收，也不能把正面素材转换为侧视图。可显式选择 `generate-parts.sheets=["limbs"]` 一张四完整肢体候选，必须经Codex实际裁片与关节审核后用 `apply-part-layout` 接入；默认body/arms/legs保持兼容。

### 完整部件图优先（1.9.1）

默认图片任务使用 `image_preparation="asset-sheet"`，流程为：检查原图与目标视角 → 必要时准备视角 → 亿创生成一张完整 `character-assets` 部件图 → Codex核对身份、真实裁片与关节 → 组装复查 → 绑定动作 → 32帧行走和鞋底诊断 → 导出。`auto`兼容旧的按缺项补图，`preserve`只复用原图。旧骨架微调保持原素材和未要求改动的动作。

完整臂掌和腿鞋以连续加权链接入，减少独立裁切的关节裂缝；原散件图支持 `apply-source-layout`，无需生成和虚构job。部件图不要求严格合格格位，必须实际查看并按显式像素布局导入。默认策略的build要求完整素材覆盖、当前revision组装查图和 `parts_reviewed=true`。结构门禁只防止跳过准备；自然步态、原角色一致性和真实侧面仍要看实图和动作，不能保证任意图或任意动作。

参考用户提供的8套原资源后，1.9.1的完整素材默认优先 `body_layout="combined"`：主衣装不在腰带与衣摆处强拆，`torso` 的 `group="costume"` 覆盖躯干与腰胯，用真实hip→neck锚点和连续hip/torso权重。需要分片的角色可选 `separate`。结合实际远近遮挡检查图层；普通角色先使用6–8个大块纹理，复杂衣摆、头发和道具按需添加骨链，当前基础衣装网格不模拟布料物理。原集主要只有idle/run而无walk；不直接搬原跑步曲线。结构与官方runtime/部件/skin证据在 `evidence/source-spine-reference/`，源24个文件哈希保持不变。


1.9.2 新人物默认先准备侧向行走视角（正面参考先转换），再生成完整部件图；Codex 先 spine_review_parts 检查身份、轮廓、分离和肩肘腕／髋膝踝连接，裁切修整后组装、绑定并检查待机8帧/行走32帧和鞋底，定向优化后复检。多边形裁片只遮去外部像素，不补画。旧任务合同及已有rig微调不变。reference_unavailable 是生图提交前的参考图失败，不等于已生成。


### 1.9.3 头颈白块与接缝复检

新 Agent 制作／微调任务在整身待机8帧、行走32帧检查之外，须用 `spine_closeup` 查看每个最终动作的8帧头颈放大图，并用 `spine_review_closeup` 记录真实结论。检查绑定到当前导出资源摘要；修改后旧结论失效。疑似中性白底只定位，不自动判错或删除白领、眼白。硬切、缺口、色差和遮挡由后台 Codex 查看实图，未通过不交付。

`texture-repair` 在另存副本中清理明确多边形范围的残底，或从当前 rig 的实际部件／保留准备原图裁片复用像素，最多改动单片25%，不补画未知像素、不新增生图。新角色保留最多4张不可变准备图供后续修复，副本继承它们。使用者仍只给图片和需求；相机、连接、动作与鞋底检查由后台完成。完整说明在 `skills/spine-animation/references/seam-review.md`，更新安装包仍为 `/downloads/spine-animation-skill.zip`。


## 1.9.4 三视图与关节细节验收

新人物流程同批准备正/侧/背三视图与独立部件图，先检查参考一致性，再与组装比对肩臂、腿膝、发型和裙摆层级。每个动作增加躯干、双臂、双腿与完整头发的8帧局部检查，修改后重新验收。生成默认另有8张补图/修订额度，首次三视图与完整部件图各1张单独计数；max_generations=0仍禁止所有生成。不会用三视图当作可直接导入的atlas，也不把参考图或数值通过当作自然步态保证。
