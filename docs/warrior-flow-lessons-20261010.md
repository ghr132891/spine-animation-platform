# 蓝衣武者制作流程复盘 · 2026-10-10

本次已交付保留蓝衣、酒红领巾、胡须发髻与矮壮比例的待机、原地行走 Spine 4.2：16 骨骼、6 个部件。制作任务使用亿创 **GPT Image 2.5 Flare** 生成 3 张图；救回和动作修正未新增生图。此前独立的参考图通道验证另外生成 1 张图，不计入动画任务的 3 张。

| 环节 | 实际遇到的问题 | 本次处理与后续选择 |
| --- | --- | --- |
| 参考图传输 | Flare 需要可读取的 HTTPS 图片，管理员未配置对象存储 | 用独立 PNG 服务与 Quick Tunnel 提供临时链接，完成远端像素回读和真实图生图；链接 1 小时有效、重启失效，平台自动刷新，不开放工作台接口。它仍是测试通道，无可用性保证。 |
| AI 部件图 | 模型没有遵循六格解剖模板。一张实际是完整双臂、裤腿绑带、双鞋；另一张是混合上／下段，并有朝向和腕袖问题 | 先查看每个部件的真实内容，选择第一张。不能仅看格数判失败，更不能按错格套到骨架。本次用确定性裁切救回，未再抽整图。 |
| 组装 | 重复踝筒、鞋口绑带、露出的圆髋端、透明边缘白底污染，以及颈部裁切缝 | 保留一份小腿鞋口纹理、隐藏肩髋端、修补组装覆盖、只在透明邻接处去白边；原头脸和躯干保留，双脚同向。 |
| 动画曲线 | 首版错误使用 `angle`，4.2 runtime 可加载但没有读到旋转，手脚实际静止 | 改为 4.2 的 `value`，查看 parsed motion 与实际世界空间运动。3.8 使用 `angle`，不能跨版本复制字段。 |
| 步态 | 单靠腿部正弦和身体上下起伏不能证明接地 | 以脚目标求双骨关键帧，补偿身体起伏；整臂与连鞋腿连续加权，鞋底刚性。同侧手足反向，再复查 32 帧与实际不透明鞋底。 |

最终导出文件的独立检查覆盖两个动作各 33 次官方 runtime 采样：循环几何首尾误差为 0，网格权重无跨侧引用；该角色同侧手足位移相关约 −0.99，支撑期鞋底竖漂约 0.0002 单位。检查结果与最终 ZIP 的几何和贴图一致，不以“收到图”或“JSON 能加载”代替动作验收。

这次经验整理到1.8.0流程：无背包角色可请求三列一行的头／躯干／腰胯，身体、双臂、腿脚使用独立短提示词；实图未按格位输出时可通过 `apply-part-layout` 显式裁切、合成与标记关节，完整臂腿使用连续加权。要求行走的完成门禁至少16帧，并检查官方 runtime 中的可见运动、关节运动及渲染顶点相对根骨的变化；最终仍建议32帧视觉复查。静态／仅根骨移动诊断负责发现曲线或绑定错误，不认证自然步态。相关 Skill 与后台 Agent 指令同步这些规则，坐标和步态参数仍按每个角色实际判断。

新部件 API 的隔离实图验证另发现：只复用默认 guide 会在链校准后把右脸颊和胡须分给原手臂，替换后造成缺脸，且肩髋端露出。已通过该角色真实 head／torso／pelvis masks、guide 和组装层级修复，完整主体与连续腿鞋在32帧保持；初版失效图保留于 [initial-rejected](../evidence/reviewed-layout-v1.8/initial-rejected/manifest.json)。默认人形模板随后按真实肩手方向与朝向修正摆臂旋转符号，这份 [API 验证](../evidence/reviewed-layout-v1.8/manifest.json) 的同侧手足相对 hip 相关从约 +0.99 改善为 −0.994／−0.995，画面相位复查一致。仍有鞋底倾斜和接地视觉不足，不算自然步态通过，也未替换已交付角色；[数值及改前记录](../evidence/reviewed-layout-v1.8/gait-comparison.json) 保留以便复查。

仍有轻微外观问题：近肩补丁遮挡偏多，领口与远肩裁切偏硬，个别帧衣摆旁可见略方的裤腿顶部。素材接近正面，因此交付的是原视角的原地行走，不能作为完整侧身角色或真实转身效果。后续可沿已交付版本继续对话微调；需要真正侧面效果时再准备对应视角，避免重做已合格部件。

可复用的流程调整：先识别真实部件语义和可用候选，再决定裁切／连续蒙皮或补图；生成预算只限制新增图片，已有完整素材应继续完成绑定与动作。保留来源任务、候选与版本链，在最终导出 bytes 上验收。
