当前1.9.4新人物同时准备三视图参考板与部件图，首次两张基础图独立计数，另有8张补图／修订额度；详见 [三视图和细节验收](turnaround-review.md)。三视图须先确认没有身份或比例漂移，部件及组装对照通过后制作动画。下面的单独character-assets调用用于旧任务、质量修订或已有合格三视图时；新默认请求为sheets=["turnaround","character-assets"]。

# 1.9.2 侧向视角、部件检查与修整

新人物行走的默认流程先改变不适合横向走路的正面视角，再准备同向的完整部件图。严格侧面不是角度数字测试：可读的三分之四侧向也可接受，但头、衣装和双鞋须沿朝向一致；原图是身份参考，不是自动 ready。待机独立请求和明确 preserve 保持用户指定镜头。

查看实际候选后，先 `spine_review_parts`：id、生成候选job_id（原部件图省略）、camera_view、direction_consistent、identity_preserved、silhouette_intact、separated、joint_review={shoulder,elbow,wrist,hip,knee,ankle} 布尔值、verdict、reason。六项均需覆盖近远两侧。ready意味着所有部件检查项通过；needs_adjustment记录具体像素/连接缺陷及修整计划，允许用现有裁片修复后组装；unsupported不能直接接入。新合同要求这次查看与检查的图片hash、revision匹配。

裁片支持 `crop_polygon`（保留区域）和 `exclude_polygons`（去除区域），点为裁切/组合后、旋转前sprite内0–1坐标。每个多边形3–128点，最多8个排除区；不拉伸或重绘保留像素，不自动填洞。先按实图轮廓消除重复袖片、邻近碎片和白底边，再保持肩/髋安装区重叠。内部白袖口、高光不可删除。改了guide或布局要重检；组装后assess_image提供camera_view、direction_consistent和六项joint_review=true，当前assembly查图、parts_reviewed=true才可build。

最后检查待机8帧和行走32帧，检测侧向迈步、摆臂相位、接缝、鞋口、支撑/抬脚、穿插和循环；发现缺陷继续改骨骼/权重/贴图并复检，数值接地不替代自然步态和画面检查。已生成候选优先裁切复用，缺像素才能在原预算内用亿创补图；质量修订、审核拒绝和未知提交仍遵循下文停止规则。

参考图发布回读失败 `reference_unavailable` 意味着尚未POST生图。先恢复 reference ensure 再沿用原生成nonce；若已提交但状态未知禁止新抽，已有gen_id下载失败仅恢复原结果。不要把预算预留说成实际生成。

# 从人物立绘准备完整部件图，再审查组装

Codex 负责看图、判断、写提示词、标注裁片与关节并复查；亿创负责全部图片生成，平台负责裁切、组装、绑定、动作和导出。1.9.1 默认把新人物立绘准备为完整部件图，然后才绑定。完整部件图提供可用的运动图面，不保证组装正确或步态自然；图片尺寸与计划格数也不能证明素材合格。

## 先确定动作与视角

| 目标 | 检查重点 | 常见处理 |
| --- | --- | --- |
| 横向行走／跑步 | 侧面或轻微三分之四视角，鞋尖朝向一致，双脚和摆臂可用 | 视角不合适先补立绘，再准备完整部件图 |
| 待机／呼吸 | 原视角能否保持完整轮廓，胸腹与肩部是否可动 | 正面立绘可作为部件图参考，不为了待机强制改侧面 |
| 跳跃／抬手 | 下蹲或伸展时露出的腋下、腰、掌心、鞋底是否存在 | 补相应部件；超出当前动作能力则说明限制 |
| 转身／多方向 | 是否有需要的前／后／侧视图 | 先准备缺少视图；多张图本身不等于已实现多方向骨架或3D转身 |
| 非人形／复杂动作 | 结构、透视、关节是否适配当前平台 | 单独判断，不套双足行走模板；无法适配时如实返回 |

不要把鞋和小腿分开误判为必须重绘：Spine 可用独立部件，但需要鞋口遮挡、关节重叠和正确权重。背手、交叉腿、正面强透视或截断脚掌，常常需要补图。

## 默认流程与兼容策略

`spine_submit` 示例：`{nonce, image_path, requirements:"保留脸、服装、比例与配色，先检查视角并准备完整角色部件图，审查裁片、关节和组装后制作待机与自然行走", image_preparation:"asset-sheet", max_generations:8}`。

| image_preparation | 处理方式 |
| --- | --- |
| `asset-sheet`（新图片默认） | 检查立绘和 guide，必要时补视角；以合格立绘为参考生成完整 `character-assets` 部件图，默认保留连续主衣装，经真实布局审查和组装复核后绑定 |
| `preserve` | 只用已有像素，不生成、不换原图；用户要求不生图时同时明确 `max_generations=0` |
| `auto`（兼容旧流程） | 原图合适时不生图，仅在动作实际缺视角或部件时按需准备 |

默认max_generations=8用于立绘、改视角、补图和质量修订；首次turnaround与character-assets各1张另外计数，最多合计10张。基础图再次生成属于修订，计入8张。用户已经提供可用的完整部件图时，记录 `source_kind="asset_sheet"`，实际检查后用 `apply-source-layout` 接入，不再次生成相同图。`max_generations=0` 禁止所有生图，但允许检查、裁切、组装和绑定现有素材。先复查原图与已完成候选能否提供完整、同身份的部件；预算用完不能成为放弃可用素材或跳过验收的理由。只有确实缺少必要图面而授权预算无法补足、生成状态未知或身份改变无法修好时停止，保留任务及可用部分，报告具体缺项。

后台工具 `spine_assess_image` 的结论记录在 `spine_status.image_assessments`：ready、needs_view、needs_parts、unsupported。记录实际图片哈希、目标动作、观察／目标视角、缺失部件、原因、版本、`source_kind`（`character`／`asset_sheet`）和 `parts_reviewed`。它记录 Codex 的视觉判断，不是像素规则识别。原立绘 `ready` 只能说明该立绘的动作适配判断；`asset-sheet` 策略不能据此直接 build。当前部件已审阅并接入、实际查看当前 revision 的 assembly 后，再记录 `ready, parts_reviewed=true`。guide、应用新立绘或部件变化后须重新查看对应图片并记录当前版本结论。

按以下顺序完成新人物制作：

1. 用 `spine_image, view="image"` 查看当前实际原图，辨认完整立绘还是已提供部件图，并记录相应 `source_kind`。完整立绘是比例和姿态参考；先校准 guide 的归一化 landmarks 与完整 settings，核对真实肩、肘、腕、手和髋、膝、踝、鞋端位置。guide 修改后复查并记录当前 revision 的适配结论。部件图格位不是角色身体坐标，不能把格子中心直接写进 guide。
2. 按目标动作判断视角。需要调整时先记录 `needs_view`，再调用 `generate-view`；应用合格新立绘后复查身份、视角和 guide。不将全部走路角色强制改为90度，也不靠旋转骨骼冒充新的侧面图面。
3. 立绘合格后，查看 `generation-plan`，用 `generate-parts` 的 `sheets=["character-assets"], body_layout="combined"` 准备完整部件图；实际衣装适合独立腰胯时可选 `body_layout="separate"`。上排主体和下排四条完整链采用同一相机与比例；无背部道具时 `include_back=false`，保留相应空位。已有部件图则跳过生成，直接按实图的衣装结构审查和接入。
4. 生成候选用 `spine_image, view="candidate", job_id="实际候选编号"` 查看整张部件图和每块有效组件；用户原部件图用 `view="image"` 查看并记录当前 revision 的 `source_kind="asset_sheet"`。对照原立绘核对脸、配色、服装、近／远侧差异、完整掌和整鞋，以及动作将露出的遮挡图面。用真实裁片、链和关节 pins 接入：生成候选用 `apply-part-layout`，已提供原部件图用 `apply-source-layout`。具体坐标规则见下文。
5. 用 `spine_image, view="assembly"` 查看当前 revision 的组装图，检查比例、接缝、遮挡、重复原袖／原腿、脸和衣摆的完整轮廓，再记录 `ready, parts_reviewed=true`。用户原部件图仍保留 `source_kind="asset_sheet"`。`asset-sheet` build 门禁需要已审阅的 head、torso／pelvis 覆盖、双臂与双腿鞋，以及当前 revision 的 assembly 查图记录；完整主衣装的 `group="costume"` 同时满足 torso 和 pelvis 覆盖，不要求再提供独立 pelvis。记录原图 ready 或收到生成图不满足门禁。
6. 绑定和制作后，用匹配 runtime 的实际渲染检查运动；行走最终查看32帧并运行真实鞋底 `spine_contact`。材料检查、组装检查与动作验收分别给结论。

## 提示词要随动作变化

1.9.1 使用 `animation-parts-v9`，按需求的主要语言组织简洁正向美术描述。中文要求用中文模板，英文要求用英文模板；Spine、GPT Image 2.5 Flare 等产品名和动作／文件标识可保留，不将其视为混合语言错误。用户的设计要求要保留，不能靠替换几个词改变角色。模板明确角色素材切片、服装与配件、完整手掌和鞋、闭合轮廓、圆润连接边缘及格间留白；必要的连接、朝向与实际部件含义仍要清楚。

先锁定原角色肖像、头饰、肤色、衣服版型、比例、配色和道具。只改变目标动作需要的视角／姿势。完整角色画面留边、背景干净，成对素材可区分；需要补齐的是服装与配件被遮挡的图案。Codex 仍在原图和候选图中检查真实手掌、鞋、关节及遮挡；精简生成描述不会取消这些质量检查，也不把服装术语当作隐藏敏感内容的代称。

横向走路的中文示例：“保留参考角色的肖像、服装、配色和道具。朝右的轻微三分之四正交站姿，完整角色留边。袖装自然垂落，末端素材完整可读；成对裤装与鞋有清楚间隔，两鞋尖朝右，裤装插接部分进入鞋口。背包为独立可读配件。”抬手动作则描述袖装展开后所需的完整连接图案和末端素材，不沿用只强调鞋尖的走路模板。用户要求明确侧面时，肖像、主衣片、腰部衣片、裤装和双鞋保持同一侧面视角；头身朝侧面但一只鞋仍正面不能算适配完成。先定向补不足的视图或部件，再重新检查身份和动作适配；骨骼旋转不会补出另一视角的图面。

1.8.2按用户的明确相机意图组织提示词：profile／正侧面强调真实侧面，near-profile／轻微三分之四保留该目标，不将所有走路角色硬改90度。正／背面要求也不能被默认朝右的侧鞋覆盖。严格侧面允许远侧表面保持自然遮挡，缺失部分后续定向补成独立部件；“双臂全部露出”和“保持严格侧面”不能靠转成三分之四同时满足。相机意图计划不识别实际图像，候选仍须重新视觉评估。

近侧和远侧衣饰按原图分别描述。单侧肩补丁、袖口饰边或裤腿补丁只保留在原侧，不能自动镜像到另一条肢体；原图确有双侧饰件才保留两份。补被挡住的连接面时延续相应衣料，不猜测新增饰件。对比原图、部件图与组装图检查重复；把远侧多余补丁藏进身体并不保证摆臂时不会再露出。

部件提示词说明实际需要的连接结构，例如“图左／图右完整手臂连续包含肩、肘、腕和手掌”“图左／图右完整腿连续包含髋、膝、踝、绑带和整鞋”“双鞋鞋尖朝同一目标方向，裤装插接部分进入鞋口”。实际完整臂或连鞋腿可以作为连续加权素材，已有完整关节无需为了模板额外切断。格位、间距和背景要求帮助拆分，但不能据此假设模型一定输出指定格数或每格指定部件；绑定协议中的部件名与 pins 字段保持原语义。

`character-assets` 是一张3:2的4列2行图，下排始终请求与原立绘图左／图右对应的完整带掌臂、完整连鞋腿。`body_layout` 控制上排主体：

| body_layout | 上排从图左到图右 | 实际部件与绑定 |
| --- | --- | --- |
| `combined`（新人物 asset-sheet 流程默认） | head、从衣领经腰线／腰带到衣摆的连续主衣装、可选 back、空格 | head 加整衣装及四条完整链，共6块或带 back 的7块；主衣装以 torso 的 `group="costume"` 覆盖 torso／pelvis |
| `separate` | head、torso、pelvis、可选 back | 独立头、躯干、腰胯及四条完整链，共7块或带 back 的8块 |

连续外套、围裙、长袍或跨腰线的图案通常适合 combined；实际服装分层、腰胯遮挡与动作需要独立控制时可用 separate。以角色的真实连接和最终组装结果选择，不照搬其他角色的切片数。`include_back=false` 时对应 back 格留空，不新增背包。`body_layout` 用于生成计划与 `generate-parts`，原部件图按实际内容接入，无需为套用布局重绘。可用 `instructions_by_sheet={"character-assets":"这张完整部件图的要求"}`，每组最多400字，不与非空共享 `instructions` 混用。

`character-assets` 必须单独选择，不能与其他部件组重复请求。旧 body／arms／legs 和显式 limbs 仍用于 `auto` 兼容流程或确有局部缺项的制作：body 无背包时为 head／torso／pelvis 三列一行；用 `instructions_by_sheet={body:"身体要求",arms:"手臂要求",legs:"腿脚要求"}` 分别约束所选组，每组最多400字，不混共享 `instructions`。先看实际生成计划，再提交；生成后仍按实图复核。

旧 `sheets=["limbs"]` 用一张2×2图请求四条完整链：上排图左／图右完整臂包含肩、肘、腕和手掌，下排图左／图右完整腿包含髋、膝、踝及鞋；关节不拆开，双鞋朝指定方向、鞋底水平，保留参考侧角。对应部件名为 l-upper-arm／r-upper-arm／l-upper-leg／r-upper-leg。可选择 `["body","limbs"]`，但 limbs 不能与 arms 或 legs 在同一请求重复选择。`instructions_by_sheet` 可包含 limbs，每组仍最多400字；兼容流程只缺一条链时，不盲目补全全部素材。

`character-assets` 与 limbs 的生成计划和候选均标记为 `requires_reviewed_layout=true`，不能使用按固定格位拆分的旧 `apply-part-sheet`。Codex 必须看真实部件，检查掌、鞋、关节、方向和边界后，使用下述 `apply-part-layout` 给出裁片及实际 pins。生成提示词要求的格数不保证实图一定遵循；不合格布局不能靠默认格位强行应用。

生成使用平台当前配置的 provider/model。亿创使用 HTTPS input_images；OpenAI Images 兼容 API 使用 multipart PNG 上传，并支持 url/b64_json 返回结果。只在 HTTPS 传输模式下要求发布参考图。供应商拒绝／任务失败如实报告，不自动切换服务或以文字描述重抽冒充参考编辑。

## 按原因处理失败，最多一次质量修订

首发就使用清楚的美术制图表达。默认完整部件图一次请求；兼容或局部补图只选择实际缺项。分组用于减少无关要求、改善布局和保持可拆分性，不用于降低审核命中率或规避拒绝；它仍会按张数占用同一个 `max_generations`。失败分为以下情况：

| 已确认的情况 | Codex 的处理 |
| --- | --- |
| 提交状态未知、无生成编号、提交超时 | 保留 nonce、原请求和已存记录；查询同一任务或报告需核实，不换新 nonce 重新生成 |
| 同任务查询、下载网络失败 | 只重试查询或下载；使用已存 gen_id，不改提示词、不新增生图 |
| 内容审核拒绝、IMAGE_RECITATION、IMAGE_SAFETY 或其他明确审核拦截 | 停止这一生成流程并报告具体拒绝原因；不改词、拆组、换图／裁图、换模型或供应商规避 |
| 生成结束但原因不明、没有有效输出 | 报告已有任务记录和不明确原因，不能假设是可补做的质量问题 |
| 已收到并查看有效图片，具体视觉／布局质量不合格 | 先检查能否裁切、拼接或复用已有合格部分；确实需要新图时，在剩余预算内最多一次精确改写或按实际缺项分组补做 |

质量补做先记下原 job_id／gen_id、具体缺陷、已复用的部分和改动计划，再为真正的新生成使用新 nonce，保留原候选及关联说明。只改具体问题，例如统一两鞋方向、保持单侧袖口饰边、补齐服装图案或分离可用切片，不重抽已合格整套角色。按组补做若需要多张，每张均占预算；剩余额度不足则继续使用现有合格素材或报告缺项，不增加额度、不无限改写。只有实际查看后的质量不合格可以走此分支，供应商失败和审核拦截不能伪装为布局问题。

再次补做仍不合格则停止新生图，保留可用成果并说明限制。用户后来明确发起新的修改需求属于新的请求，仍需遵守该需求预算及相同的拒绝／未知提交处理规则。提示词优化与接口模拟检查不能代替新的实图验收，也不保证模型永远接受或准确遵循描述。

## 平台自动准备参考图链接（1.7.1）

以下为 `reference_transport=https-url` 的流程。当前若为 `multipart-file`，平台生成内部参考句柄并直接上传文件，不公开图片、不使用这些链接发布步骤。内部句柄不是可供浏览器或外部服务访问的 URL，不要手工改写。

使用者把图片和动作要求发给 Codex，Codex 调用 `spine_submit` 即可。服务器接收图片后会正规化尺寸和像素；后台 Codex 按准备策略检查视角与部件，`generate-view`／`generate-parts` 需要参考图时自动完成以下步骤：

1. 优先复用当前图片哈希匹配的缓存，或与当前原图完全一致的已应用亿创候选图链接。
2. 缺失时由平台发布当前原图：已有可用 S3 兼容存储优先；未配置存储时可使用管理员已启用的 Cloudflare Quick Tunnel 临时 HTTPS 通道。上传者或图片服务均在平台服务器，使用者无需对象存储账户、亿创登录或浏览器操作。
3. 核对远端图片与当前原图像素一致后持久缓存；按图片哈希复用。S3 签名链接过期会刷新；临时通道图片有效期为1小时，服务重启后旧链接失效，平台在下一次需要参考图时自动更新缓存。换图后使用新图的缓存，不误用旧图；调整关节但原图未变时可复用有效缓存。
4. 将链接交给亿创 Flare 生成。发布和校验本身不提交生图、不占生图张数；上传失败时不改成无参考图生图，不更换生成供应商。

普通制作不需调用额外参考图工具。诊断或预先准备时可调用 `spine_reference`：`{action:"ensure", kind:"character", id:"当前角色编号", revision:当前修订号}`。工具检查任务拥有范围和当前 revision，完成后台发布或复用后返回链接。未加载 MCP 时，使用 `python3 scripts/spine_workflow.py reference --base http://服务器IP:8780 --request 请求.json`，请求内容相同。

`GET /api/characters/{id}/reference` 只查询当前图片与缓存，不触发上传。需要准备时使用 POST 同一路径及 `action:"ensure"`、当前 `revision`，并附本地操作保护头。旧 `prepare`／`register` 仍用于兼容性查询、导出或登记既有精确 HTTPS 链接，不能把网页登录上传作为普通制作前提。

管理员在服务机器打开 `http://127.0.0.1:8780/settings.html` 选择参考图发布方式。无需存储配置时，安装官方 `cloudflared` 客户端到项目 `tools/bin/cloudflared` 并启用临时 HTTPS 通道；不需要 Cloudflare 账户、域名或存储密钥。通道连接独立的 loopback PNG 图片服务器，仅允许随机 token 对应的 PNG GET/HEAD，不开放工作台端口、目录列表或其他接口。公开链接供亿创读取，持有链接者在有效期内也能访问对应图片，不要求邮件或浏览器认证。

S3 兼容存储仍是可选方式：配置 endpoint、region、bucket、access_key_id、secret_access_key、prefix 与签名链接有效期；已有 ready 配置优先使用。只有服务机本地可保存发布配置，密钥不返回客户端、不放入 Skill／MCP 安装包。调用前可用 `spine_sources.reference_upload.ready` 查询是否已就绪；未启用通道、客户端缺失或网络无法连通时保留任务并报告具体平台原因，不要求普通使用者登录亿创、复制链接或提供任何存储／亿创密钥。原图已合适或已有有效参考链接时，无需因发布未配置而阻止制作。

[Cloudflare 官方说明](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)将 Quick Tunnel 定位为测试与开发功能，没有 uptime 保证，每次启动域名可能改变。平台管理缓存刷新不等于永久链接或生产可用性保证；服务机器与网络仍需保持运行。

代码支持与真实链路验收分别说明：启用状态或模拟测试不能证明免登录参考图和 Flare 补图已实际验证通过。只有完成实际发布、远端像素校验和生成结果复查后，才能给相应验收结论；发布已成功而补图尚未完成时分别报告，不把收到图片当作动作验收通过。

## 识别与接入真实部件布局

先看原图、候选整图和每个有效组件，记录其身份、左右侧、内容、边界、方向与关节锚点。一格可能是完整带掌手臂，也可能只含上臂；腿可能带鞋、带绑带，或另有一块独立鞋。按实物定义裁切与锚点，不把“六个连通域”直接等同于模板的“上臂／前臂／大腿／小腿／鞋”。模板不匹配时保留候选，不按错格应用到原角色；先检查当前平台是否支持显式部件布局接入，再选择对应能力。

生成候选通过 `spine_character` 的 `action="apply-part-layout"` 接入，`data={revision,job_id,parts}` 使用当前 revision 和真实 job_id。它复用已查看的候选，不发起生图；候选必须属于当前原图。用户提供的原部件图通过 `action="apply-source-layout", data={revision,parts}` 接入，无 job_id，不应先生成同一套素材。这两个入口按相同的实际裁片和关节点规则建立显式部件层，不识别解剖、不按格子自动绑定，也不补缺失像素。

每项使用现有部件 `name`，`box=[x0,y0,x1,y1]` 是生成候选或原部件图原始尺寸的像素裁切范围，右／下边界不包含在裁片内。查看器缩放过图片时，按真实宽高换算裁片，不直接提交预览坐标。主体按实际布局使用 head、完整主衣装或独立 torso／pelvis，以及实际存在的 back。完整主衣装须用 `name="torso", group="costume"`，显式提供最终 sprite 中髋／腰位置的 `start_pin` 和颈部位置的 `end_pin`；这两个点分别对齐 guide 的 hip 和 neck。costume 不能同时设置 chain，且覆盖 torso／pelvis，不能再导入与其覆盖冲突的独立 pelvis。其他单段附件可给 `start_pin/end_pin`。

完整臂用 `name=l/r-upper-arm, chain="arm"`，并给 `pins={shoulder,elbow,wrist,hand}`；完整腿鞋用 `name=l/r-upper-leg, chain="leg"`，并给 `pins={hip,knee,ankle,toe}`。所有 pins 都是最终 sprite 内的 `[x/宽,y/高]`，不是整张部件图的坐标。依据原立绘和真实衣饰确认 l／r 所对应的图左／图右和近／远侧，不凭格位推断。

裁片确需旋转时可给该项 `rotation`，角度范围 -180 到180，正值为逆时针，省略为0。平台先裁切或拼接，再旋转并扩展画布；先以真实部件朝向确定旋转，再标注旋转后最终 sprite 内的 pins。它适合用户已有部件图中横放或斜放的头、完整链等，不是另一视角的补绘。坐标与锚点须对应最终结果，不复用默认坐标或其他角色的数据。

需要把同一张部件图内的裤腿与鞋合成连续素材时，可改用 `canvas=[宽,高]` 与 `pieces=[{box:源图像素范围,dest:canvas像素范围},...]`；后片覆盖前片，pins 相对于最终 canvas（设置 rotation 时为旋转后的 sprite）。通过裁片范围和覆盖只保留一套绑带／鞋口。当前 guide 的链首尾关节决定整体大小与朝向，中间 pins 校准肘、腕、膝与踝；先检查 guide，不能靠裁切数据掩盖错误比例。完整链会覆盖同侧原上段、下段和手／脚附件，用相应三骨连续加权；接入后用 `spine_image` 查看当前 revision 的 assembly，再记录部件已审阅的评估并 build。

完整主衣装会作为连续 weighted mesh，在 hip 与 torso 两骨之间加权，使腰带、衣摆和上身衣料保留在同一张图面；它没有独立 pelvis 附件。当前基础 costume 只有这两骨参与权重，不能据此宣称已经复刻原 Spine 的多骨衣摆动作或自动衣摆物理。复杂长衣摆、袖尾或挂饰可按实际需要另外增加骨链并验证权重和动作，具体见 [骨架微调](rig-refinement.md)。

链校准会改变原图的默认分区。完整部件图应为 head 和实际的 costume 或 torso／pelvis 建立实图审阅的显式部件层；兼容流程保留原头脸和衣服时，先按实际轮廓记录主体显式 masks，再调整 guide 和组装层级。复查完整脸颊、胡须、领巾、腰带与衣摆有没有被重算的臂腿分区偷走。连续链接缝正确不代表主体仍完整。遮罩只用于这个角色的实图，不复制另一角色的轮廓或坐标。

素材完整且已隔离时，优先复用它们完成制作：裁切所需完整部件，以关节覆盖和连续加权保持连接；鞋底需要刚性时将鞋部分绑定到足骨，避免随小腿软拉伸。也可沿用独立上下段或鞋附件，只要真实接合与遮挡正确。不能因为格数不符合模板便重抽整张，也不能因剩余生图预算不足而放弃可用部件。绑定前核对真实髋／膝／踝位置、父子关节偏移和可达骨长，不用显示 length 或另一角色比例代替。

裁切后在透明或深浅两种背景检查 alpha 与轮廓。仅清除外部白底混合边缘，不删除袖口、绑带或高光等内部浅色材质。组装时将补图的肩端／髋端藏入躯干或衣摆，并避免原袖、原腿与新部件重复；小腿和鞋口出现两层绑带、额外踝筒或露出开口时，保留一份正确连接纹理即可，不能简单移动骨骼掩盖错误像素。

## 素材、组装与实际动作验收

部件图先对照原立绘检查身份、原脸、色彩、比例、近／远侧衣饰和肢体数量；核对完整手掌、整鞋、肩肘腕与髋膝踝、鞋口和动作会露出的遮挡图面后再裁切。看当前 revision 的组装图检查混入像素、粘连、重复衣饰、接合、脸与主体轮廓及遮挡。guide 或部件变化后重新评估当前版本。完整部件图不保证姿态、比例或步态自然。

要求行走时完成门禁至少16帧，并确认匹配 runtime 中有可见运动、关节运动及渲染顶点相对根骨的变化；最终用32帧检查实际动作、肩袖接缝、肘腕、手掌、脚腿接合、鞋底落地、手脚相位、轮廓、穿插与循环。runtime motion report 的静态／仅根骨整体移动提示用于发现曲线或绑定错误，不认证自然步态。结构通过、部件审阅通过或收到候选图，均不等于动作已合格。

有目标动作所需的缺失部件时记录 `needs_parts`／`needs_view`，不能同时声明 `ready`。`asset-sheet` 策略必须完成真实部件层和组装审查，不能用原立绘 ready 跳过；`preserve`／`auto` 的合适原图仍可按其策略制作。生成预算为0仍可检查、裁切和绑定已有合格原图或候选。素材身份与遮挡检查、有效动作、鞋底接地分别给结论；行走最终调用1.8.2的只读 `spine_contact`，并实际查看32帧。工具缺少映射或可信鞋底元数据而返回 `not_assessed` 时，不能改写成接地通过。

1.8.2新建人形模板采用60%支撑期、256个均匀采样区间及相位边界、Spine4.2绝对坐标 Bezier 曲线（`bezier-hermite-v1`），默认 `lift=0.07`；左右腿按较短真实链长共用步幅和同一场景速度，避免腿长不同导致两侧支撑脚滑动不一致。只有完整刚性脚或已复核的完整腿鞋链可用完整不透明 alpha 下轮廓估计真实鞋底，不按固定64点删减轮廓，并结合实际骨长下压髋部使 IK 目标可达；不完整混合素材会保留 `ankle-fallback` 和 `requires_visual_review=true`。数学目标与 Bezier 近似不等于最终 runtime 严格 C1，也不代表已实现脚跟／脚尖滚动；采样区间数不是预览帧数。即使接地记录、可达计数或相关性正常，仍需看32帧中实际鞋底、鞋口、遮挡和体型；具体方法见 [骨架微调与补图](rig-refinement.md)。

近正面或强透视素材可制作原视角的待机与有限行走摆动，但不能将其描述为已获得完整侧面角色或真实三维转身。保留当前视角还是补更适合横向走路的视角，以用户要求和实际生成结果为准；交付时说明仍受原图透视限制的部分。


1.9.3部件准备须保留肖像底端至原领口的连续连接图面与覆盖余量，不按固定高度截断alpha；只保留参考已有衣饰。组装后每个动作进行8帧头颈放大检查，见 [局部复检与原像素修复](seam-review.md)。白底定位不替代视觉判断，不能全局删白或靠骨骼遮盖缺图。
