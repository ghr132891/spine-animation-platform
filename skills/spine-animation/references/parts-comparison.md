# 标准模板与补全分层实测

用户提供标准部件图并要求验证生成质量时，先做素材试验，不在验收前交付新动画。模板是质量/拓扑参考，不能把原模板贴图冒充新生成结果。

## 当前真实能力

平台 `parts-lab` 是管理员可选试验流程，尚未替换普通用户默认生成。两条路线共享冻结的完整人物母版：
- `template`：当前生图服务接收母版和从真实 atlas 解包的标准部件板。它是 **reference-image-only**，没有实现 ControlNet 或硬几何锁定；不宣称图块尺寸、轮廓和关节一定吻合。
- `see-through`：调用官方演示实际推理，保存事件编号、原始 PSD 和 RGBA 图层。演示服务的配额与可用性不作生产保证。用户明确选择本路线才向该服务上传任务图，不把亿创的持续公开授权扩展到任意第三方。

绿马甲实测发现：See-through 能补出袖装、保留背包，但 PSD 的 legwear 双腿合层、footwear 双鞋合层；不能将合层硬切为“完整两腿”并声称遮挡已补齐。其图集预览按字母排序，**实际绘制顺序必须读 PSD**。模板参考生成也会漏颈部插接区、改变袖片和鞋的轮廓；即使有六块完整外观也不能直接套旧网格。

## 平台操作

本机管理员 API（均带 X-Spine-Local: 1）：
1. `POST /api/parts-lab/create`：`nonce` 为固定32位十六进制编号，`character_id`、`template_project_id`，可选 `template_png` base64。PNG 尺寸须与 atlas 完全一致，当前只支持6件模板。优先使用与用户标准图匹配的真实 atlas/JSON；不靠图块中心猜骨骼。
2. `POST /api/parts-lab/{id}/run`：`route=template` 或 `see-through`。可独立启动；同编号恢复已有结果。模板每个试验最多1张，额外修订需继承原制作预算，不能用新编号绕过额度。两路线对比仅在用户要求时执行，正常任务不重复跑两模型。
3. `probe-bones`：`probe_bones={arms:[近侧根骨骼,远侧根骨骼],legs:[近侧根骨骼,远侧根骨骼]}`；按真实模板校准一次，不能套绿马甲骨骼名到别人模板。
4. `inspect`：`route`。模板通过官方 runtime 采样静态试拼及肩髋正反摆开；无动画剪辑、无新 rig。See-through 读取原 PSD 位置与顺序。可选 PSD 依赖见仓库 requirements-parts-lab.txt。Node 必须可用。
5. `GET /api/parts-lab/{id}` 和 `/parts-lab.html?id={id}` 查看状态、原图与结果；`files/` 下载实际图/PSD。
6. `review`：提交当前 inspection 的 `digest`、`verdict=ready|needs_repair`、具体 `reason`、布尔 `checks={complete_parts,assembly_matches,spread_intact,connection_geometry,appearance_matches}`。缺件/合腿/大轮廓偏差不能 ready。改变贴图或模板坐标后旧验收失效。

无 API 时，仓库 `tools/parts_lab.py` 提供同名 action；`--data` 读取 JSON，`--route` 指定路线，`inspect --node` 可指定实际 Node 路径。这是 Codex/管理员操作，不让普通使用者输入命令。

## 验收与后续

查看完整裁片、试拼、双向摆开及肩颈/裤腰/鞋局部，对比母版和标准模板。模板的参考轮廓只用于测量，不直接裁掉新图超出的像素。旧网格可能裁断新鞋，出现这种情况须重新设计适配或局部生成，不以可加载当通过。

完整部件图和全部关节连接合格后，才导入同坐标角色，按 complete-assets-v1 再检验实际导入摘要，随后制作待机/行走。试验页面中的素材通过不自动批准任何 rig。失败时交付真实素材与原因，保留旧动画并明确它不是本轮成果。

## See-through 合腿结果的局部续修

复用实际 PSD 的头脸、颈片、衣装、背包和双臂，仅补出缺少的逐侧完整腿鞋。补图需包含圆滑的大腿插接端、连续膝踝、裤脚和整鞋；不把合并裤层沿中线硬切后声明完整。保存原 PSD、补图原件、服务回执或生成文件哈希及采用版本，未采用的修订也计入实际生图次数。

平台 `app/semantic_completion.py` 提供同坐标组合、按两对实际锚点做等比旋转定位、独立腿重复检查及可见纹理恢复。完整腿按实际髋、膝、踝、脚尖记录 pins；原图裤腰留在主体衣装，覆盖腿根的真实插接余量。颈片可与头脸按原 PSD 顺序合成，头颈置于领口后，复检摆头时的遮挡。不同人物必须重新查看关节点，不能套用绿马甲坐标。

恢复原裤料时，归属蒙版只控制哪些可见纹理写回到已补全部件，不能裁掉完整部件的隐藏轮廓。恢复范围必须位于已对齐的新部件内部，避免从另一条腿带入悬空细条；原裤脚与新裤脚位置不同则不要重叠粘贴。融合仅限下面已有实心裤料的交接区，之后再次检查独立图与两侧极值。

透明 PNG 要按 alpha 实际合成到深浅底检查；透明像素的 RGB 可能仍保存色雾，不能仅凭忽略 alpha 的预览判定为残留或重复生图。独立残点优先使用平台 `finish_material` 的局部 remove-specks，保留有效鞋底和发丝。

用 `install-canvas-layers` 导入独立角色副本，启用 `complete-assets-v1`，查看并记录当前摘要的部件、试拼、双向摆开结论。只有实际通过才 build。新动画仍须独立复检；不能把静态素材通过等同于待机/行走通过。
