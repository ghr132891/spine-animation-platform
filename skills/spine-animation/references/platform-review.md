# 平台复检与边缘修复（1.10.0）

## 平台与 Codex 的分工

平台负责：冻结同一导出资源、决定动作采样和真实骨骼区域、两路受限并发渲染、复用采样/PNG/磁盘证据、真实鞋底测量、alpha连通块候选扫描、局部像素处理、资源变更后的验收失效及记录约束。Codex 负责实际看图，判断造型、材质、自然步态和遮挡，并给出异常区域；无需自行循环导出、拼帧、写临时修图脚本。

`spine_review_bundle`：
- 传 kind=rig/project、真实 id；默认所有动作，可指定 animations（1–8个真实名字）。
- 一次生成 manifest；其中 panels 给出 key、animation、anchor、frames 和原尺寸 image_url，contact 是数值报告，alpha_diagnostics 是每片的小连通块候选。
- 再传相同参数与 panel="p0" 等实际 key 读取 PNG。后台只有读取图片后才计入已提供证据；准备整个包不会自动写 ready。
- 看过全部所需图片后，后台用 `spine_review_regions(kind,id,reviews=[...])` 一次记录真实结论。每项字段同 spine_review_closeup；重复区域、旧摘要、缺图、缺布尔项等会使整批不写入。
- 修改任意贴图/骨架/动作后重新获取清单，不复用旧图或旧结论。相同资源和渲染代码可直接读取磁盘缓存；进程重启不用重算已完整保存的证据。未完成的包重试可接着准备，不生图。
- 新生成素材导入时，平台自动清理 alpha≤3、面积≤4、且不连接实际图面的独立插值点；保留所有 RGB。用户原素材导入保持原流程；不会全局收边或把裙料透明区误判成残片。

## 明确范围的边缘修复

先看局部动作图和目标部件。`material-finish` 的 part 是目标贴图 ID，reason 写明实看缺陷，operations 的 polygon 为目标 sprite 内0–1多边形。原 erase/edge-cleanup/opacity 保持兼容，增加：

- `remove-specks`：max_pixels 默认4、允许1–32；可用 max_alpha（1–255，默认255）只处理弱像素。基于**完整贴图**的8邻域连通性，只删除完全在选区内的小组件，ROI截断不能把合法细发丝变为孤点。删除后 alpha 精确为0，不能因选区边缘抗锯齿留下半透明残点。
- `edge-trim`：pixels 默认0.5、范围0.05–1；对已确认污染的边缘做有限亚像素alpha收边，保留RGB和内侧像素。不要多次堆叠；不用于缺覆盖的接缝，不选鞋底接地区，也不用于透明衣料或合法发丝。

较大残条用已确认轮廓的 erase；肩部透底缺口要恢复同源RGBA和覆盖量，不能继续收边。现有边界已正确但纹理内有色块时，alpha操作不会自动重新绘制正确色彩。缺图仍走实际补片流程与原预算。

蓝裙案例：后发右下有细长棕条和裁切边界最后一行的蓝色孤点；腿缘有裁切阶梯及弱插值尘点。先去掉确认的细条，再对完整组件清孤点；腿部仅在鞋口以上局部收边，鞋底不透明像素与骨骼/idle/walk JSON 不变。原头部裁片还有少量独立点，须一起检查实际图层来源，不能只看命名为 back 的一片。此案例的像素范围只适用于当时素材，不固定到新人物。

## 验收与速度边界

待机全身8帧、行走全身及双腿32帧，其他局部8帧；看实际发梢、两侧腿缘、肩颈接缝、裙料透明层与鞋底接地。连通块为零不等于美术通过；小点也可能是合法装饰。大型贴图的自动扫描可返回 not_assessed，不能视为没有问题。

减少的是重复计算、工具编排及记录往返；首次全量渲染、必要视觉判断和亿创排队仍需时间。不要把缓存命中时间当成端到端首次生成时间。平台仍不保证任意素材免视觉检查、任意跨骨架动作重定向或真实布料物理。
