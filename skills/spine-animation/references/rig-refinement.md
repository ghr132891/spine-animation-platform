# 骨架微调、缺失部件与摆臂

头颈白块、发丝截断或连接缝先读 [局部复检](seam-review.md)：1.9.3提供实际8帧放大图和基于原像素的texture-repair，旧版“无法放大”限制已解除。

## 改姿势前检查素材

新人物立绘默认走1.9.1的 `asset-sheet` 准备流程：先以完整立绘校准 guide，按动作确认视角，必要时 `generate-view`，再生成完整部件图并审查裁片、pins 和组装。参考 [图片准备](image-preparation.md)。用户已有完整部件图时用 `apply-source-layout` 导入，不重复生图。这个前置流程不要求把已验收的已有 rig 重新生成为部件图；连续微调沿用最新实际交付的骨架与素材。

先看原动作和实际部件，再查看对应 mesh 的加权顶点，确认哪些骨骼真正控制它。按 Spine JSON 的 bones 索引解析权重，不能仅靠 slot.bone 或名称猜测。背手、背包遮挡、交叠双腿的贴图可能只有可见部分；把它移出来会露截口。

参考已有 Spine 工程时，先读实际 JSON／atlas、skin 的附件与原贴图，确认哪套 skin 可用和动作会显示哪些部件。有些源 skin 缺少手臂，不能把缺图当作应模仿的角色结构。`guke`／`zhujue` 中已查看的6–8纹理角色多用整块衣装的 weighted mesh，可作为保留服装连接的结构参考；它们的 run／idle 不能充当当前角色已经验收的 walk。`xiaochushen` 的复杂半身烹饪骨架不适合作为全身双足行走基线。按当前角色建立关节、权重、遮挡和动作，再用实际渲染验收，不照抄其他骨架的精确骨长、时间、关键帧或曲线；同一实际源骨架的连续微调则保留已验收数据。

素材完整时直接调整。缺失素材而用户只授权骨骼微调时，说明具体缺项并取得补图选择；用户已明确要求 AI 补全时沿用该授权，不再次询问相同确认。纯调骨骼或节拍无需生图。

## 补图接入已有版本

当前后台对已有 rig 不提供任意局部补绘。max_generations 不能让 rig 自动具备这个能力。由当前调用端可用的亿创生成／编辑入口补全，或使用用户提供的完整部件，然后通过 spine_refine.part_images 上传。没有该入口或缺少素材时说明限制，不以素材换皮的轮廓锁定模式冒充结构补全。

提示词明确：原角色是身份、风格与肤色参考，原部件是补全目标；只输出所需部件，保留衣袖／材质／光照，画出完整关节、前臂、手腕和手掌；独立透明背景，部件与邻接图面分离，关节边缘有少量覆盖余量。尺寸、姿势和朝向根据真实角色决定，不能将某一个角色的比例或朝向通用于其他骨架。检查实际生成图和 alpha；先复用合格部分，确需重做时在剩余预算内最多一次针对已确认视觉缺陷的质量修订。审核拒绝或未知提交状态按 [图片准备](image-preparation.md) 处理，不通过改词、拆图或换模型规避。

补图同时保留源图头身脚的相机与近／远侧差异。单侧肩饰、裤补丁或袖边不得复制到另一侧；隐蔽安装面补成相应基础衣料，不虚构饰件。用户明确要求 profile 才强调真实侧面；远侧遮挡可另补部件，不能转镜头来满足“全露出”并仍宣称严格侧面。完整 limbs 只是可选素材形式，不为已经合格的分段附件或原有 rig 强行重做。

`part_images=[{"name":"fullarm_near","image_path":"/绝对路径/fullarm_near.png"}]` 中的文件位于调用电脑，由 MCP 上传 PNG 像素，名字唯一且只含字母数字、下划线或连字符。最多8张，每张6MB、2048×2048，总计12MB。原贴图不被覆盖，新部件先导入未绑定状态；在 requirements 中明确蒙皮、绑定与哪个动作使用它。导入完成不代表绑定已完成。

例如：保留原 setup/idle/run；在 walk 的原手臂插槽增加完整臂附件，通过 attachment 时间线切换；为新臂添加肩肘骨骼并建立实际 mesh 权重，保留腿部时间线。近远手臂的 drawOrder 以真实画面决定。若需重排骨骼，正确重映射所有原加权顶点索引。原手臂继续用于原动作，新增部件只在目标动作显现。

已有完整隔离的手臂或腿鞋时，可保留整块纹理做连续加权网格，按真实肩／肘／腕、髋／膝／踝建立骨链。不要为了固定格位或骨名制造截口；分段附件也可以使用，接合须有足够重叠与正确 drawOrder。圆形肩端、髋端应藏进主体，鞋底以下保持足骨刚性，避免走路时鞋尖变软。接入后检查原袖／原腿是否仍叠在新部件上，以及白底抠图边缘是否污染透明 PNG。每种连接方式按实际素材选择，不把某一次角色的尺寸或关节坐标通用化。

对仍有角色原图与当前补图 job 的流程，1.9.1新人物默认 `generate-parts, sheets=["character-assets"], body_layout="combined"`：一张3:2、4列2行的完整部件图，上排头／连续主衣装／可选背部道具／空格，下排图左／图右完整带掌臂和完整连鞋腿，共6块或带背部道具的7块。按实际服装和组装验收可选 `body_layout="separate"`，保留头／torso／pelvis 独立分片。`auto` 兼容流程仍可按缺项选择 body／arms／legs 或显式 limbs。完整部件图和 limbs 均带 `requires_reviewed_layout=true`，旧 `apply-part-sheet` 禁止接入；Codex 必须实看每块部件，通过 `apply-part-layout` 给真实裁片、chain 和 normalized pins，先核对当前 guide，再用 `spine_image` 查看当前 revision 的 assembly。已提供原部件图改用 `apply-source-layout, data={revision,parts}`，无 job_id；旋转裁片可给 `rotation`（-180到180），pins 按旋转后最终 sprite 标注。详细坐标规则见 [图片准备](image-preparation.md)。

完整主衣装通过 `name="torso", group="costume"` 导入；必须给最终 sprite 中 hip 位置的 `start_pin` 与 neck 位置的 `end_pin`，同时覆盖 torso／pelvis，不再配置独立 pelvis，也不同时设置 chain。基础 costume 是连续 weighted mesh，仅由 hip 和 torso 加权；需要额外衣摆、袖尾或挂饰运动时，另行编辑骨链、蒙皮与时间线，并查看32帧实际形变。选择 combined 不会自动建立这些骨链，也不提供自动衣摆物理或完整复刻参考工程 run 的能力。

`asset-sheet` 策略完成 build 前，需要 head、torso／pelvis 覆盖、双臂和双腿鞋的已审阅部件层、当前 revision 的 assembly 查图记录，以及 `ready, parts_reviewed=true`；costume 可同时满足 torso／pelvis 覆盖，原立绘 ready 不满足门禁。实际检查原脸、配色、近／远侧不对称衣饰、完整掌和整鞋、接缝与遮挡图面。该入口不等于已有任意 rig 获得局部补绘 API；已有 rig 的部件导入仍走上面的 `part_images`。头身与双鞋的相机视角须一致，不能把正面鞋旋转成侧面鞋。素材完整也不保证步态自然，须继续验证实际绑定和动作。

CLI 回退：`refine --task 上一版任务 --requirements "绑定补图并调整摆臂" --parts /绝对路径/parts.json --state /绝对路径/v2-task.json`。parts.json 与 MCP 的 part_images 格式一致，不含令牌或 Base64。后续查询使用同一 state/nonce，避免重复提交。

## 摆臂节拍检查

编辑动画时按目标 runtime 写曲线：Spine 4.2 的 rotate 关键帧使用 `value`，Spine 3.8 使用 `angle`。不能跨版本照搬字段。先从匹配版本 runtime 的 parsed timeline 和世界空间采样确认曲线被读取、目标移动部位确实变化；顶点有限、循环首尾相等或 JSON 已加载，都可能同时发生在一条被忽略而静止的动画上。静态待机部位无需强行运动，但用户要求行走或摆臂的部位不能仅凭结构校验交付。

1.8.0的 runtime motion report 区分可见运动、关节相对父骨的运动、渲染顶点相对根骨的运动、静态与 `rootOnlyMotion`。要求行走时，完成门禁需要可见运动、关节运动及渲染顶点相对根骨的变化，并查看至少16帧；最终用32帧实际渲染复核，并调用 `spine_contact` 检查真实鞋底。根骨整体平移或身体一起上下浮动不能替代走路。该报告用于定位曲线／绑定问题，不判断动作是否自然，也不替代接地和画面检查。

先查看16/32帧动作，再用 spine_gait。提供真实的身体参考骨骼 anchor、投影轴 axis=x/y 和同侧 `pairs=[{"arm":"真实前臂或手骨骼","leg":"真实足部骨骼"}]`。默认测 arm 骨骼末端和 leg 骨骼起点，可用 arm_endpoint/leg_endpoint 改变。该诊断在32个时间点测相对身体的位移：

- correlation 接近 -1：所选轴上反向运动；接近 +1：同向；接近0可能是四分之一周期偏移，也可能是运动过小或映射/观察轴不合适。
- insufficient-motion：不能据此断言正确或错误。
- suggestedArmPhaseAdvanceSeconds：按 sampled(t + shift) 约定给出使所选两条位移曲线最反向的时间平移建议。应用前核对朝向、步态和完整循环，不能机械套用正弦或余弦。
- loopMaxVertexError：完整渲染几何的首尾差异。只适合用户期望循环的动作；接近零也不保证脚掌接地或没有穿插。

平台默认新建人形行走模板已按真实肩到手的方向与角色朝向选择摆臂旋转符号，避免局部骨轴不同造成同侧手脚同向。它只影响新建模板，保留已有 rig 的动作；导入或微调其他骨架仍按实际绑定与采样调整，不能照搬模板公式。反向相关改善也不代表鞋底姿态、接地或动作自然已通过。

1.8.2新建人形模板采用60%支撑期、256个均匀采样区间并额外纳入相位边界，按 Spine4.2绝对坐标 Bezier 写入曲线，元数据标记 `motion_curve="bezier-hermite-v1"`，默认 `lift=0.07`。左右腿按较短的真实链长确定共同步幅，使用同一场景速度；不能分别按各自腿长推算不同地面速度来掩盖滑步差。数学脚目标在连接处设计为位置与速度连续（C1），但目标设计和有限 Bezier 近似不保证最终 runtime 严格 C1，也没有脚跟着地／脚尖蹬地的分段滚动。最终仍用32帧实际预览复查，不把采样区间数当成已查看帧数。

完整刚性脚或已复核的完整腿鞋链使用 `opaque-lower-envelope`：保留实际不透明 alpha 下轮廓的全部有效点，不按固定64个均匀点删去可能决定接地的鞋底低点，再估计水平鞋底姿态。按真实关节偏移求骨长、下压髋部，为全部脚目标和身体起伏留出 IK 可达余量。不完整混合分段仍用 `ankle-fallback`，其 `requires_visual_review=true` 必须保留为待检查项。

读取 skeleton.gait 可以诊断支撑比例、鞋底来源、髋下压与不可达采样，不能把字段存在、不可达计数为零或水平角估计当作接地已验收。轮廓识别可能受缺鞋、混入像素、角度或 alpha 污染影响；检查真实鞋底和鞋口、模板是否改变矮壮比例、支撑期是否滑步及摆动期是否穿插。若素材视角不适合横向走路，先补一致的头身和双脚视角；改变骨旋转不会生成侧面图面。新模板的改进不自动覆盖已有任意 rig。

仅替换需要调整的完整动画或相关曲线，保留其他时间线、约束和 Bezier 曲线。变更后重看每个最终动作。先用16帧定位，摆臂、绑定或步态调整的最终版本使用32帧检查肩袖接缝、肘弯、手掌、前后遮挡、腿鞋连接及循环衔接。采样同侧手／足相对真实身体骨的位移，不把骨骼名字、肢体看起来左右摆或正弦曲线相反当作相位证据。

走路还需单独检查支撑期与摆动期。依据动作实际设计识别支撑区间，测真实不透明鞋底或有意义的足部特征点；透明贴图矩形的最低点不等于鞋底。支撑期关注脚高、鞋底姿态和对应地面速度下的滑动，摆动期关注抬脚与穿插。原地走与向前位移的参考系不同，不能机械要求每种动画的支撑脚世界 x 都固定。双骨 IK 或预先求解的关键帧可用目标脚轨迹补偿身体起伏，并保持鞋底刚性；这是处理滑步的选择，不是所有骨架必须采用的模板。实际骨链长度与轴向以世界空间关节为准，显示 length 不能替代真实父子偏移。

1.8.2的 `spine_contact` 是只读真实鞋底诊断，不生图、不上传、不改动作。公共入口二选一：直接提供 `kind="rig"/"project", id`，或已交付的 `task_id, artifact_index`；不为直接交付的 rig 虚构 Agent 任务。后台 worker 使用已持有的 kind／id。`options` 可提供 `samples`（默认128，最多512）、统一 `scene_speed`、`stance`、`ground_y` 和显式 `pairs=[{slot,foot,hip,knee,phase,arm?}]`；映射必须来自实际附件与骨骼，phase 以当前动作设计为准，不能照搬另一角色。这里 `scene_speed` 是整个场景在 runtime 世界 X 的平移速度：向右为正、向左为负；支撑脚自身速度应与它反向抵消，不能把脚速直接当作场景速度填写。

先检查已有 `sole-contact-v1` 元数据是否对应当前素材和动作；没有可信元数据且未给显式映射时，工具返回 `not_assessed`。读取真实鞋底在支撑期的高度、姿态及同一场景速度下的滑动，再与32帧画面核对；不得用不同左右场景速度分别抵消滑动。诊断不能认证侧面视角、自然步态、遮挡或全部皮肤与帧；数值改善而画面仍有凹口、重复肩饰、穿插或不合适视角时继续定向修正。只有匹配当前导出文件的诊断与视觉复核支持时，才给对应接地结论。

把预览里的具体问题用于下一次 `spine_refine`，只改对应骨骼、遮挡、贴图或动作，沿用已验收素材与版本链。匹配 runtime 的结构与数值校验、真实动作采样、视觉复查分别给结论，不把任何一项作为其他项目已通过的证明。

CLI 回退：`gait --task 任务 --animation walk --request /绝对路径/gait.json`，gait.json 提供 anchor、pairs、可选 axis。此操作只读，不生图、不改动作。
