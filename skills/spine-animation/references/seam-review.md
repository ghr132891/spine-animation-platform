# 头颈接缝与白底残留（1.9.3）

整身联系图会把颈部缩成几十个像素，不能代替局部验收。新任务携带 `neck-seam-v1`：最终每个动作都用 `spine_closeup` 看8个真实 runtime 姿态的放大头颈图，再由后台 `spine_review_closeup` 记录结论。默认 anchor=head；导入骨架按实际头颈骨选择。看下巴至领口、颈后发丝、近远肩端和遮挡关系。贴图、骨架或动作改变后，旧资源摘要下的检查全部失效，须重新查看。

`spine_closeup` 支持 task_id/artifact_index 或 kind=rig/project,id，二选一；可检查直接交付的 rig，不为它虚构任务号。公开入口只读，后台记录验收。疑似白色组件仅用于定位：白领、眼白和白发都可能合法，不能按数值直接删除或宣称不合格。矩形／水平硬切和色差由 Codex 对实际放大图判断，未查看或仍有缺口不能 ready。

## 不生图的定向修复

先看目标贴图和对应原图。新角色构建在 rig 中保留最多4张准备阶段的不可变图片；`spine_inspect.material_sources` 给出实际ID与尺寸，用 `spine_image view=material,part=ID` 查看。副本保留这些参考；旧 rig 未必有，不能伪造来源。已有完整补片也可按原流程 part_images 上传。

后台 `spine_edit_rig` 支持 `texture-repair`：

- `part` 为目标贴图ID，`reason` 说明已观察到的缺陷。
- `white_regions` 为目标 sprite 内0–1多边形，最多8个；只清除其中已确认的中性白底，不全局删白。
- `copies` 最多8片：`source_part` 或 `source_material` 取当前 rig 实际像素，`box` 是源图像素范围，`dest` 是目标贴图像素范围；`crop_polygon` 可限制源裁片内的归一轮廓，然后缩放并组合。两种来源二选一。

修复最多改变单片25%像素，保留尺寸、骨架与动作，另存并记录来源摘要。更大变化使用完整真实补片并重绑。它不绘制未知像素；缺必要图面时按原生图预算和授权处理，不能因一次接缝检查自动新增付费调用。

优先清残底、恢复连续原发丝／颈部连接、修遮挡或少量覆盖余量。切片连接不应靠固定高度横切 alpha；不能从另一角色复制坐标。修后重新查看每个动作局部图、待机8帧、行走32帧及实际鞋底接地。局部、动作和数值检查分别给结论；无法确认时报告具体缺项，不交付成“全部已修复”。

## 肩缘、裙缝与透明材质（1.9.5）

看到浅边先定位来源：可能是别的裁片残留、裁切白底，也可能是正确的白领。检查各张实际 RGBA 部件和动画遮挡，先删除明确重复的碎片，再做小范围边缘修整。不要整图删白、羽化整个人物或缩小步幅掩盖问题。硬二值裁切会产生阶梯；局部轮廓使用超采样覆盖率，保留原 RGB、画布尺寸和绑定。

`spine_edit_rig` 新增 `material-finish`，和 `texture-repair` 一样须先看当前资源的局部图；只在副本上执行，资源摘要改变后旧检查失效。操作字段：`part`、`reason` 和 `operations`（1–16项）。每项 `polygon` 是**目标部件**内0–1多边形，可使用：

- `kind="erase"`：清理已确认重复或混入的像素；4倍超采样轮廓，只改 alpha。
- `kind="edge-cleanup", radius=0.6`：去除边缘一像素尖刺并小范围柔化 alpha，半径0.1–2像素，不扩展原来的空白、不改 RGB。
- `kind="opacity", top=0.4, bottom=0.95, start=1, end=0.5, reference_note="实际材质依据"`：只在所选服装区域渐变乘 alpha；top/bottom 是整张部件的归一化高度。参数按该角色原图确定，禁止把示例比例用于所有裙装。保留实色内衬、领口、皮肤和鞋的遮挡，检查前后纱层叠加后的实际效果。

透明度判断须对照原图。绿幕或白底合成图通常无法唯一恢复原 alpha；只可称“匹配轻纱观感”，不可声称无损恢复。原图是实色衣料时不要主动透明化。不要让透明贴图暴露未补齐图面。

平台的躯干、双臂和双腿8帧放大图末行自动附两种姿态的浅底/深底对照。检查肩后是否残留重复轮廓、裙缝是否连续、有无针孔，以及纱层能否透出后方图面。它们是定位证据，不能自动认证美术正确。离线帧图按图集 Linear 模式采样，仍需网页复检；采样改善不能替代真正贴图修复。最终待机8帧、行走32帧、所有局部区域及真实鞋底接地检查都须基于最终相同资源摘要。

本次蓝裙实例：头部裁片残留手臂条造成肩部浅边；裙缝残留肤色像素与硬二值边缘造成破碎轮廓。分别在头部裁片清掉重复条、在衣装片清掉缝内碎片，局部柔化轮廓，再仅对下摆匹配轻纱 alpha；保留上衣、肤色与鞋、骨骼及两套动作。遮挡问题需要裁片与分层一起核对，不能只看白色像素计数。

肩端残边也可能是过度羽化形成的透底缺口：先在深底辨别“残白”与“缺 alpha”。有历史完整裁片时恢复对应连接区的原始 alpha 与必要覆盖量，尺寸有变化则按实际裁片映射；不要继续侵蚀/羽化该接头。只修材质时保留动作与鞋底，重新核对资源摘要和接地。
透明背景 RGB 曾被清零时，不能只把 alpha 拉高，否则会露出黑块；恢复覆盖须从同源保留裁片复制成对 RGBA，并验证尺寸映射与接头色差。


## 前摆不自然：先查动态控制（1.9.6）

蓝裙旧版前摆使用两条大腿旋转最大值的72%；大腿动画本身带整体正偏转，令衣摆整个循环保持13°–22°前翘。另以x正负硬分前后权重，使相邻网格运动不连续。透明度、边缘清理与鞋底接地无法修复这类动作错误。

解决：保留服装像素、透明度和腿部曲线，恢复中性垂落；独立小幅周期随动并加入相位滞后，从腰到下摆逐渐加权，前后区域连续混合。平台对新建group=costume的连续衣装在髋下延伸超过腿长60%时自动启用long-hem-v1；不是任意衣装识别或物理碰撞。短衣和导入骨架不自动改写。

先对照原图/三视图确认垂落和开衩，再查骨骼旋转与网格。不要把大腿绝对角度、左右腿max/min直接当衣摆摆幅。现有rig在副本中按真实绑定调整；不要套用蓝裙坐标、删除动作或缩小腿部步幅。

复检最终动作的躯干与双腿放大图、32帧行走：前摆是否一直支起，裙缝是否折角/交叉，遮挡是否符合开衩，首尾是否跳动，透明层是否正常。查看实图才能通过；garment_motion.requires_visual_review和接地数值不等于美术通过。复杂裙装仍穿插时调整网格/分层或补齐图面，不能扩大摆幅冒充布料模拟。


## 图面完整性与动态遮挡（1.9.7）

蓝裙实图验证中，运行时、循环和鞋底接地数值通过，但放大行走仍发现后裙片上端断开、大腿轮廓异常、肩缘浅缝。自动任务先拦截了不完整素材；额外裁切组装也未通过最终视觉验收。这说明必须把素材完整性和绑定/动作质量分开判断。

修复顺序：
1. **完整衣料**：检查每片前后衣料从腰部到裙底是否真实连续。裁去原腿只会留下缺口；优先复用同角色已有完整图面，确实缺图时用亿创 `generate-parts` 的 `sheets=["costume"]`、`instructions_by_sheet={"costume":"当前缺片及原材质要求"}` 补一张完整衣装。该组只输出 torso、group=costume，须实际查看并通过 reviewed layout 导入；hip/neck pins 按新图标定。原有生成额度、质量修订次数和审核停止规则不变。
2. **图层分离**：主衣装只保留衣料，臂腿不能带重复胸衣、裙片，衣料中不能固定带着原腿轮廓。正面/侧面近远侧一致；有意开衩与自然遮挡不能误当缺口。
3. **肩部覆盖**：匹配肤色或衣料、留真实重叠区；在最大前后摆臂位置检查圆帽边、浅边和漏背景。局部去底/清残片只能修已有像素，不能靠增透明度或整体挪位掩盖缺失连接。
4. **后发绑定**：导入 back 前先标定 back 定位点，核对导入部件、组装部件和输出槽三者一致。老数据若缺定位点也会明确报错，修正 guide 后再组装，不默认猜位置。
5. **动态复核**：待机8帧、行走32帧；七个区域每动作放大8帧，腿部检查包含裙缝，深浅底对照检查材质边缘。鞋底数值通过只能说明所测接地条件，不认证膝形、裙缝和遮挡。

新任务由平台后台 Codex 记录以下结构化字段，普通使用者无需填表：
- `spine_review_parts` 和 `spine_assess_image(parts_reviewed=true)`：`material_checks={connection_overlap,garment_continuity,layer_separation,silhouette_valid,edge_clean}`，每项均为布尔值。
- `spine_review_closeup`：torso 与 upper-leg 使用上述五项；head 与 upper-arm 去掉 garment_continuity；__hair__ 使用 silhouette_valid、edge_clean、occlusion_valid。
- ready 必须全部为 true。确有缺陷时用 needs_adjustment/needs_parts/needs_repair，reason 写出位置与处理方向。不存在相关衣料时，该项表示无对应缺陷并在 reason 说明。不要为了过门禁填全 true。
- 候选图的像素变更使部件审查失效；任何素材/骨架/动作变更使最终资源摘要下的视觉审查失效。部件像素连通数只提示风险，不把原设计的开衩或多个合法装饰自动判坏。

平台提供独立衣装补图入口、结构错误拦截和验收记录约束，不保证每张生成图自动合格。不能将额外 Codex 修复或直接另存的 rig 宣称为原自动任务完成。


## 腿根覆盖、大腿挤尖与裙片遮挡（1.9.9）

本次蓝裙先出现迈步过大、腿根外露，扩大髋部固定权重后又出现大腿被拉成楔形。隔离腿部与组合图比较后发现：大腿本体连续，前裙片同时遮住膝部的大部分轮廓，进一步放大了尖角观感。修复须分清图面、网格和遮挡，不能只降低弯腿幅度或扩大遮盖。

1. 对照当前原图与三视图，确认本来允许的开衩、实色后片及轻纱区域。生成提示已增加短圆润连接余量、完整连续活动轮廓及侧面衣片间距约束；提示词并不保证质量。
2. 默认查看组合腿部；怀疑变形时，用相同 animation/frame_count/anchor 生成 `isolated=true` 对照。隔离图没有衣裙，不能用来证明衣装覆盖合格，平台不会给它最终审查信用。
3. 单独腿变形：检查髋膝鞋定位、极端姿态、蒙皮过渡长度和网格密度。髋部约束应限制在实际被衣装盖住的短安装区，沿原图渐变到大腿权重。保留正常腿宽与连续轮廓。
4. 单独腿正常、组合挤尖：按本角色原开衩修正衣片边缘/局部网格或层级，使膝附近的可见轮廓连续；保留腰部、后侧实色遮挡和原轻纱。不要凭空切掉整片裙装或缩细腿。
5. 集中修好后重新检查最终摘要：长衣装 walk/run（包括 walk_loop）双腿32帧、idle双腿8帧，其他区域按原要求；还有整身动作、循环与鞋底接地。检查每帧极值，勿只看联系图缩略图。需要时放大具体帧。

`spine_review_closeup` 在此契约的腿部区域必传 `garment_checks={hip_coverage,thigh_contour,knee_readable,garment_clearance}` 四项真实布尔结论；ready须全部通过，needs_repair可记录失败。`knee_readable` 表示符合原服装的自然可见/遮挡轮廓，不要求长裙露膝。只认当前资源摘要的组合图，帧数不足、隔离图、旧检查不能通过最终交付。自动识别范围是平台生成的 long-hem 衣装及对应骨骼；未知导入骨架仍须人工智能视觉判断，不声称覆盖所有衣装。

此次个例使用了缩短髋部混权区和膝附近前裙局部偏移。具体像素、比例与方向只对该角色有效，未固化为所有新角色的参数。修复优先已有像素与绑定，新增图片仍受现有预算及生成规则约束。

## 前后衣领与校准版本（2026-10-14）

先核对组装页的 character_id/revision 和最终 rig 的 canvas_layers.character_id、来源修订。旧人物组装、另存素材和已导出动画是独立快照，不能把旧组装页正确当成当前动画正确；骨架直接修复不会反向同步素材校准。交付同时给最终 rig 校准入口，明确静态素材与运行时的区别。

颈部被衣服压住时，不要把“前领盖住颈根”简化成“整片衣服压在整颗头之前”。检查原图前后领结构：后领在颈后，前领在颈前。需要时从已有衣料中保留单独前领覆盖层，继承原躯干网格和权重，按「躯干/后领 → 头颈 → 前领」排序。不能整颗头强行置顶导致颈底覆盖前领，也不能靠上移头部或擦掉所有领口修遮挡。检查动作是否有 drawOrder 时间线会覆盖设置姿势的排序。

绿马甲此次复检发现：原先整片领口盖住头颈，形成灰色封口且后领也挡住颈部；此前“连接连续”的判定遗漏了前后空间关系。仅连接无裂缝不等于遮挡正确。每次都须把静态母版、设置姿势和最终动态颈部放大图并排对照，保留旧版，基于新摘要复检全部动作。

### 平台执行接口与新版验收

新任务使用 `assembly-connections-v3`；保留 v2 的腰胯/背包检查，head 额外记录 `rear_collar_behind_neck`、`front_collar_in_front`、`runtime_pose_consistent`。无衣领的角色说明不适用且不存在相应遮挡冲突。不能将“连接无裂缝”视为遮挡正确。颈部行走32帧、待机8帧；`spine_review_bundle` 已统一提供，旧 v1/v2 任务兼容原字段。所有布尔项必须来自当前资源实图。

已观察到前后领遮挡冲突时，优先用 `spine_edit_rig` 的 `occlusion-overlay` 操作，参数为 `part`（源贴图ID）、`source_slot`（后层插槽）、`subject_slot`（头颈插槽）、`name`（唯一新层名）、`polygon`（源贴图归一坐标）和 `reason`。平台复制源附件的尺寸、网格和权重，保留RGB与原素材；仅提取选区alpha，排序为源层→主体→前景。可用于实际存在的前景覆盖边，不能补画缺失内容。动态 drawOrder、源插槽/附件动画和不兼容附件会明确拒绝，须专门适配。不得套用其他人物的选区。此操作经当前资源 closeup 后才能在 Agent 流程使用，执行成功不授予视觉通过。

新构建的 `assembly_source` 记录人物ID、生成时revision与素材/定位摘要，另存记录 `derived_from_rig`。result 页面显示来源版本；旧数据缺版本就明确未知，不补猜。网页素材校准对应当前人物，另存动画对应独立快照，二者不能混作验收证据。
